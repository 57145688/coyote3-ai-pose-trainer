# 手动控制 Android 0.1

独立原生 Android BLE 测试应用，适用于 Android 12 及以上，面向郊狼三代。不是网页套壳，无需官方 APP。本版本只提供本人手动设备控制，不包含摄像头姿态识别或姿态到电刺激的联动。

## 已实现

- 附近设备运行时权限、按三代广播名称扫描、由本人选定设备。
- 服务验证、通知订阅、连接后请求双通道归零，收到匹配回执才允许开始。
- 本人确认开始，每次强度从零开始；A/B 分别手动 ±1。
- A/B 本 APP 上限、独立协议频率参数、独立波形幅值和三种共享包络选择。所有参数只在停止时应用。
- STOP 清空请求，发送双通道绝对零和零幅值波形；收到主机回执才标记归零。
- 30 秒会话上限，APP 离开前台时请求停止，回执或写入超时进入停止／未知状态。
- 无网络权限，无账号，无云端视频或数据上传，不自动重连或恢复输出。

## 手机安装

1. 下载 `ManualControl-0.1.apk`，打开安装文件。按 Android 提示为用于打开 APK 的应用允许安装来源。
2. 关闭现有浏览器控制器的 BLE 连接，以及可能占用主机的其它 APP；原网页不需要删除。
3. 打开“手动控制”，授权“附近设备”，点击扫描，再点选列表中的主机。
4. 等待“主机已回报归零”。此前开始按钮不可用。主机型号不符、回执缺失时不会启用控制。
5. 参数初始为零。修改设置后点“应用设置”，由本人点击开始，再操作 A/B 按钮。30 秒后自动结束。

这是开发测试签名 APK，不是经过实机验收的正式发行版。已完成编译和签名验证，没有在你的手机、主机或人体上试用。首次验收不要连接人体。

## 本地软件验证结果

694 项纯 Java 断言通过：上限钳制、停止后禁止增加／重启、启动归零、协议频率边界、15 个序列号及三种包络的 STOP 报文全部为零。Android 源码通过 API 35 编译，APK 通过签名验证。

上述测试不等于蓝牙时序和硬件输出验收。每 100 ms 尝试发送一帧，但等待上次 GATT 写入及主机回执，不排队堆积波形；实际频率受主机回执和 Android 调度影响。

## 不连接人体的实机验收

| 项目 | 操作 | 预期 |
| --- | --- | --- |
| 权限拒绝 | 拒绝附近设备权限 | 显示未授权，不扫描 |
| 连接 | 选择三代主机 | 先请求归零，收到匹配 B1 回执才启用开始 |
| 停止状态 | 点击 A/B +1 | 不发送增加指令，提示尚未开始 |
| 上限 | 将本 APP 上限设为 1，波形幅值保持 0，开始后多次 +1 | 请求不超过 1，回报与请求分别显示 |
| STOP | 会话中点 STOP，随后点 +1 | 请求清零，不能再次增加，须收到归零回报后重新手动开始 |
| 生命周期 | 切后台或锁屏 | 请求归零；回来不会恢复会话 |
| 断联 | 关闭主机 | 显示状态未知，不显示已确认归零 |
| 超时 | 等待 30 秒 | 结束会话并请求归零，不自动开始下一轮 |
| 波形验证 | 使用合适的隔离台架／假负载，由具备设备测量能力的人核对输出 | 实测行为与协议相符；不以手机显示代替输出测量 |

任何失败都应记录 APP 文本日志、Android 版本、主机版本，停止后续测试。设备失联后 APP 无法确认或保证主机物理停止，必须使用主机实体控制确认。不能把 0–200 协议范围理解为人体安全范围。

## 当前限制

- 不读电量；不把未知电量显示为 0%。
- 不写设备持久化 BF 设置，因此不会覆盖主机频率／强度平衡参数。界面上限仅约束本 APP 发出的命令，不是主机软上限，也不约束物理旋钮。
- 姿态训练、语音纠偏、动作库与历史记录未实现于这个 0.1 手动版。
- 回执延迟或设备不返回所需确认时会拒绝启动／停止；需实机核对后才可调整超时策略。
- 无法处理手机断电、进程被系统直接终止时的最后一条无线消息，不能承诺失联后设备状态。
- 此测试 APK 使用开发签名，正式发布前须使用所有者管理的签名和完成实机验证。

## 源码构建

提供标准 Android Gradle 工程文件，AGP 8.7.3，Gradle 8.9，JDK 17，SDK 35。安装对应 Gradle 后从项目根目录运行 `gradle :app:assembleDebug`。也可用带 JDK 17、SDK platform 35 与 build-tools 35.0.0 的 Linux 环境运行：

```sh
ANDROID_SDK_ROOT=/your/android-sdk bash build-with-sdk.sh
```

输出在 `out/ManualControl-0.1.apk`。源码 ZIP 不含本次签名私钥，重新构建会使用新的开发签名。
